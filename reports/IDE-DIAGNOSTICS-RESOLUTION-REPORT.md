## 2. The Five Original Diagnostics

Prior to resolution, the Antigravity IDE Problems panel and status bar reported 5 errors associated with `tests/unit/rules.test.ts`:

| Diagnostic Code | File Path | Line & Column | Severity | Error Message |
| :--- | :--- | :--- | :--- | :--- |
| **TS2307** | `tests/unit/rules.test.ts` | Line 1, Col 18 | Error | `Cannot find module 'node:test' or its corresponding type declarations.` |
| **TS2307** | `tests/unit/rules.test.ts` | Line 2, Col 20 | Error | `Cannot find module 'node:assert' or its corresponding type declarations.` |

| **TS5097** | `tests/unit/rules.test.ts` | Line 5, Col 37 | Error | `An import path can only end with a '.ts' extension when 'allowImportingTsExtensions' is enabled.` |

### Root Causes
- **Missing Node.js Declarations (TS2307):** Neither `node_modules` nor `@types/node` existed in the project. Node.js built-in module prefixes (`node:test`, `node:assert`, `node:fs`) could not be resolved by TypeScript's type-checker without ambient declarations.
- **Explicit `.ts` Extension Disallowed by Default (TS5097):** TypeScript defaults to prohibiting explicit `.ts` extensions in import specifiers unless `allowImportingTsExtensions` is explicitly enabled in `tsconfig.json`.

### 5.2 Category B: `exactOptionalPropertyTypes` Mismatches (TS2375, TS2412, TS2379, TS2322) — 5 Diagnostics
These errors occur because `tsconfig.json` has `"exactOptionalPropertyTypes": true`.
Under this strict option, an interface property defined as `prop?: T` permits omitting the property entirely (`{}`), but rejects explicitly assigning `undefined` (`{ prop: undefined }`). If explicit `undefined` is valid, the type must be declared as `prop?: T | undefined`.

| File | Line:Col | Code | Diagnostic Message | Root Cause & Recommended Fix |
| :--- | :--- | :--- | :--- | :--- |
| `src/cli/cli.ts` | 223:11 | TS2375 | `Type '{ ... categories: RuleCategory[] \| undefined; ... }' is not assignable to type 'EffectiveScanOptions'` | `EffectiveScanOptions` defines `categories?: RuleCategory[]`, `skip?: RuleCategory[]`, etc. But CLI options parser instantiates them as `undefined` when flags are omitted. **Fix:** Update `EffectiveScanOptions` in `src/core/types.ts` to allow `| undefined` on optional fields (`categories?: RuleCategory[] | undefined;`). |
| `src/core/dedup/finding-collector.ts` | 85:7 | TS2412 | `Type '{ file: string \| undefined; line: number \| undefined; column: number \| undefined; } \| undefined' is not assignable to type 'FindingLocation \| undefined'` | `FindingLocation` defines `column?: number`. When assigning `input.location.column` (which may be `undefined`), TypeScript rejects explicit `undefined`. **Fix:** Update `FindingLocation` in `src/core/types.ts` to `file?: string | undefined; line?: number | undefined; column?: number | undefined;`. |
| `src/core/orchestrator/scan-orchestrator.ts` | 66:71 | TS2379 | `Argument of type '{ maxFileSize: number \| undefined; }' is not assignable to parameter of type 'FileDiscoveryOptions'` | `FileDiscoveryOptions` defines `maxFileSize?: number`. Orchestrator passes `options.maxFileSize` (which can be undefined). **Fix:** Update `FileDiscoveryOptions` interface to `maxFileSize?: number | undefined;`. |
| `src/rules/code-quality/code-quality-rules.ts` | 208:3 | TS2322 | `Type '... evidence: string \| undefined ...' is not assignable to type 'RuleFindingInput'` | `RuleFindingInput` defines `evidence?: string`. In `code-quality/build-error-suppression`, `evidence` is assigned `lineContent ?? undefined`. **Fix:** Update `RuleFindingInput` in `src/core/types.ts` to `evidence?: string | undefined;`. |
| `src/rules/security/security-rules.ts` | 96:23 | TS2379 | `Argument of type '{ ... evidence: string \| undefined; ... }' is not assignable to parameter of type 'RuleFindingInput'` | In `security/powered-by-header`, `evidence` is assigned a nullable match expression. **Fix:** Same as above — allow `evidence?: string | undefined;` in `RuleFindingInput`. |
